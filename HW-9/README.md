Спроектировать API в Swagger-стиле. 

Часть 1 · спека: api.yaml (OpenAPI 3.0) — 4–5 эндпоинтов под РАЗНЫЕ глаголы: минимум GET-список, GET-одного, POST, PUT/PATCH, DELETE; у каждого summary, параметры, 200 + хотя бы один ошибочный код с причиной (401/403/404 — вспомните «не знаю, кто ты» vs «знаю — нельзя»); DTO-схемы в components — внутреннее наружу НЕ едет. 

Все пиши внутри HW-9

Делать будем спеку АПИ по бронированию переговорок в офисе.
Должны быть ручки:
1) Получение всех переговорок в офисе (Get):
Параметры - этаж, вместимость
Модель переговорки - id, имя, этаж, максимльная вместимость, удобства (ТВ, доска, возможность проведения конференций), возвращается массив таких переговорок
Ответы - 200, 400 (на неправильные фильтры)

2) Получение информации об отдельной переговорке (Get):
Из параметров только id переговорки.
Модель - как из первого запроса, но с расширенными полями: описание, как пройти, фото, часы работы, что-то еще может полезное про переговорку?
Ответы - 200, 404 (нет такой переговорки)

3) Получить календарь переговорки (Get):
Из параметров - обязательный id, а также параметры того, откуда смотреть (dateTime) и до куда смотреть расписание (dateTime)
Модель - обертка с описанием (id переговорки, начало и конец временного промежутка) а также массив бронирований (время начала, конца, кто забронировал, имя бронирования)
Ответы - 200, 400, 404

4) Добавить бронирование (Post):
Из параметров - id комнаты, которую бронируем. Информацию о пользователе получаем из данных авторизации (пусть будет JWT токен)
В теле: начало, конец, имя брони, комментарий к брони
Ответы: 201 (с id бронирования и созданную модель (по REST)), 400, 403 (если нельзя бронировать эту переговорку), 404, 409 (если есть пересечения с другими бронированиями)

5) Перенести бронирование (Patch)
Из параметров - id бронирования, новая дата начала, новая дата конца
Ответы: 200, 400, 403, 409, 404

6) Удалить бронирование (DELETE)
Из параметров - id бронирования
Ответы: 200, 403, 404

Также все ручки могут возвращать 401, если не смогли узнать пользователя. Также пусть каждыя ошибка возвращает машиночитаемый код ошибки и человекочитаемый код ошибки
